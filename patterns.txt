1. Strategy (Поведенческий)
   - Место применения: базовый класс BaseStrategy в quizzes/strategies/base_strategy.py; реализации — quizzes/strategies/single_choice.py, quizzes/strategies/multiple_choice.py, quizzes/strategies/text_answer.py, quizzes/strategies/matching.py
   - Обоснование: позволяет гибко обрабатывать разные типы вопросов (один выбор, несколько, текст, соответствие) без изменения основной логики проверки ответов. Каждая стратегия инкапсулирует свою логику валидации.

2. Observer (Поведенческий)
   - Место применения: базовый класс BaseObserver в quizzes/observers/base_observer.py; реализация — quizzes/observers/notification_observer.py
   - Обоснование: обеспечивает уведомление участников и организатора о ключевых событиях (начало квиза, завершение сессии, новые результаты). Реализует слабую связанность между компонентами через подписку на события.

3. Factory Method (Порождающий)
   - Место применения: quizzes/factories/question_factory.py
   - Обоснование: централизует создание объектов вопросов нужного типа на основе данных из БД или API. Позволяет легко расширять систему новыми типами вопросов без модификации клиентского кода.

4. Template Method (Поведенческий)
   - Место применения: базовый класс BaseQuizService в quizzes/services/quiz_service.py, BaseExportService в quiz_stat/services/export_service.py
   - Обоснование: определяет общий алгоритм обработки ответа участника (получение → валидация → подсчёт баллов → сохранение), позволяя подклассам переопределять только специфичные шаги (например, валидацию для текстового ответа).
