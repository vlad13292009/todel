# Правила работы с репозиторием

## Структура веток (классический GitFlow)

- **`master`** — стабильная продакшен‑версия.
  - Защищена от прямых коммитов.
  - Обновляется только через мерж из `release/*` или `hotfix/*`.

- **`develop`** — основная ветка текущей разработки.
  - Создаётся от `master`.
  - Все фичи вливаются сюда.
  - Является источником для `release/*`.

- **`feature/*`** — разработка отдельной задачи.
  - Создаётся от `develop`.
  - Мержится в `develop` после завершения.

- **`hotfix/*`** — срочное исправление критического бага.
  - Создаётся от `master`.
  - Мержится в `master` и `develop`.

- **`release/*`** — подготовка релиза (финальное тестирование, версионирование).
  - Создаётся от `develop`.
  - Мержится в `master` (с тегом) и `develop`.

> ⚠️ **Прямые коммиты в `master` и `develop` запрещены.**

## Правила именования веток

### Требования

- **Префикс**: обязательно (`feature/`, `hotfix/`, `release/`).
- **Роль**: указывать роль разработчика: `backend`, `frontend`, `realtime`, `qa`, `devops`, `docs`, `lead`.
- **Номер задачи**: из GitLab Issues (например, `16`).
- **Язык**: английский (транслит допустим для существительных).
- **Части речи**: использовать **существительные**, а не глаголы.
- **Разделитель**: дефис (`-`).
- **Запрещено**: пробелы, подчёркивания, кириллица, спецсимволы.

### Примеры

**Корректные:**
- `feature/backend-16-quiz-crud`
- `feature/frontend-24-adaptive-nav`
- `hotfix/login-error-404`

**Некорректные:**
- `my-branch` (нет префикса, роли, номера)
- `fix` (нет роли, глагола, номера)
- `add-quiz` (глагол, нет роли и номера)

## Формат коммитов

### Требования

- **Номер задачи**: все коммиты должны содержать `[#N]`.
- **Язык**: русский.
- **Часть речи**: **отглагольные существительные** — `Создание`, `Настройка`, `Добавление`, `Реализация`, `Исправление`.
- **Атомарность**: один коммит = одна логическая задача.
- **Чистота**: в репозитории не должно быть мусора (`.venv`, `.pycache`, `.idea`).

### Примеры коммитов

**Корректные:**
- `[#16] CRUD квизов (создание, редактирование)`
- `[#12] Реализация паттерна Strategy`
- `[#21] Добавление импорта/экспорта в CSV`
- `[#70] Деплой на тестовый сервер`

**Некорректные:**
- `[#16] Создал CRUD квизов` (глагол в прошедшем времени)
- `fix` (нет номера, непонятно)
- `update code` (английский, нет номера)

## Процесс разработки

### 1. Создание Issue

Создайте Issue в GitLab **до начала работы**.

### 2. Создание ветки для новой задачи

```bash
git checkout develop
git pull origin develop
git checkout -b feature/роль-номер-название
```

### 3. Работа в ветке

Работайте только в своей ветке.

### 4. Завершение работы над задачей

По завершении создайте Merge Request в `develop` с описанием:
```
Closes #5
```

### 5. Подготовка релиза

Создайте ветку `release/v1.0-mvp` от `develop`:
```bash
git checkout develop
git pull origin develop
git checkout -b release/v1.0-mvp
```

### 6. Выпуск релиза после финального тестирования

- Создайте Merge Request в `master` с описанием:
  ```
  Release v1.0.0
  ```
- При мерже **добавьте тег версии** (например, `v1.0.0`).
- **Обязательно создайте Merge Request из той же релизной ветки в `develop`** для синхронизации.

### 7. Процесс выполнения hotfix (при критической ошибке)

#### Шаг 1. Переключение на `master` и обновление

```bash
git checkout master
git pull origin master
```

#### Шаг 2. Создание ветки hotfix

```bash
git checkout -b hotfix/lead-42-login-error
```

#### Шаг 3. Внесение и фиксация исправления

```bash
# ... исправление бага ...
git add .
git commit -m "[#42] Исправление ошибки входа в систему"
```

#### Шаг 4. Слияние в `master`

```bash
git checkout master
git merge --no-ff hotfix/lead-42-login-error
```

#### Шаг 5. Создание тега версии

```bash
git tag -a v1.0.1 -m "Hotfix login error"
```

#### Шаг 6. Отправка изменений и тега в удалённый репозиторий

```bash
git push origin master --tags
```

#### Шаг 7. Синхронизация с `develop`

```bash
git checkout develop
git merge --no-ff hotfix/lead-42-login-error
git push origin develop
```

#### Шаг 8. Удаление временной ветки hotfix

```bash
git branch -d hotfix/lead-42-login-error
git push origin --delete hotfix/lead-42-login-error
```
